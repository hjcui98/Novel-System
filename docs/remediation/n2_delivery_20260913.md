关键实现点：

### 2.1 单一时序契约（不复用同一对数字）

`PlanObligation` 的时间字段语义先查清再映射：

| 字段 | 语义 | 映射到检查的哪一侧 |
|---|---|---|
| `not_before_chapter` | 该责任内容**最早**可开始触达读者（开启锁） | 阶段窗口的早边界 |
| `target_chapter_start/end` | 兑现应落在这个窗口 | 无 `not_before` 时才作为早边界 |
| `due_chapter` | 该承诺的**截止**章 | 阶段窗口的晚边界 |

`obligation_stage_windows` 因此产出 `(not_before 或 target_start, due_chapter)`，
不把 `not_before_chapter`、适用范围、`due_chapter` 和 payoff 窗口压成对所有动作通用的一对数字。
已 `RESOLVED`/`ABANDONED` 的义务不再产生窗口（责任已结束，不再锁任何东西）。

### 2.2 三种状态明确区分

| 状态 | 表示 | 宿主行为 |
|---|---|---|
| 目录不可读（没有受信 World 到达审校） | `accepted_obligation_ids is None` | `OBLIGATION_CATALOGUE_UNKNOWN` 阻断意见，点名被引用的 handle |
| 目录可读且为空 | `frozenset()` | 按"该 ID 不存在"逐条判定（`neither an accepted author constraint nor an accepted obligation`） |
| 义务存在但没有任何时间约束 | `(None, None)` | `declares no not_before_chapter, target window or due_chapter`，报为无法核验而不是通过 |
| 义务存在但宿主无窗口数据 | 映射中无该键 | `declares no chapter boundary the host can apply` |

引用义务 ID 只通过 `serves` 触发窗口需求；下层 `obligation_actions` 只问"该 ID 是否存在"，
由既有 ID 检查回答，因此不因缺少窗口目录而被误报。

### 2.3 合法铺垫与伪装揭露

`setup` 豁免边界的理由是"埋设不触及被锁内容"。宿主不判断剧情，但不再把豁免
给一个自身 `description` 就在宣称披露动作的条目：`_DISCLOSURE_ACTIONS`
（`正式揭露`/`正式推进`/`实质揭露`/`兑现`/`揭晓`/`回收`）只收录**动作词**，
不收录情节词。行动词表有意保守：单独的"揭露"或"推进"不构成证据。
约束路径与义务路径共用同一判定，因此"被引用的责任即为权威"在两条通道上一致。

### 2.4 关闭语义

`due_chapter` 关的是**事件**而不是状态：检查落在阶段窗口上，
所以"第 100 章之后仍持有铜铭"这类后续状态引用不会被当成重复发生，
而一个把兑现事件排到 101 章之后的阶段会被 `closes at 100` 拦住。

### 2.5 prompt 与 skill 同步

删除了"标签只决定是否必须填写 `serves`，改标签不能改变任何宿主机检字段"这一失实描述，
改为说明 `setup` 豁免的真实条件、无法核验窗口时的宿主行为，以及语义审查与宿主机检的分工。

## 5. 未运行项与限制

- **本阶段没有可核对的真实义务目录**：v23 全部 World 根快照的 `obligations` 均为空
  （已遍历对象库确认）。因此"真实 WorldRoot 读取路径"验证的是**路径**，
  目录内容仍由测试构造；真实义务目录要等 G0 的 STORY/ARC_VOLUME 提交才会产生。
  这条限制直接决定 D0 不能只用 v23 的既有工件。
- 义务只声明 `due_chapter` 而没有 `not_before`/`target` 时，早边界仍不检查
  （`(None, due)` 只约束晚边界）。这是"不把窗口压成一对通用数字"的直接后果，
  对这类义务继续由语义审校判定早边界。
- 行动词表是启发式：它拒绝的是"标着 `setup` 却在宣称披露"的条目，
  不判断内容本身是否是揭露。真正的语义判定仍在审校模型。
