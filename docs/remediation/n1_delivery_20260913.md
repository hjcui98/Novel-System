## 2. 源码提交与生产调用路径

责任文件：`src/novel_agent/agents/plan_reviewer.py`、`src/novel_agent/domain/planning.py`、
`schemas/stage4/PlanReview{Issue,Draft}.schema.json`。

生产调用路径：

```
PlanReviewerAgent.review
  → _accepted_obligations(...)            # 只读一次受信 World
  → apply_host_plan_review_constraints    # 所有分支共用核验结果
      → _verified_model_issues            # 结构化定位 + 逐字段核验
          → _citation_failure
              → _resolve_field_path       # 小语法路径解析，不使用 eval
              → _quote_matches            # 文本逐字 / 数值与集合按自身表示
  → 有 verification_failures 时先落盘 draft 工件，再抛 PlanReviewerInvocationError
      → PlanningContextLoopService.run 捕获 → REVIEW_REQUIRED / REVIEWER_CONTRACT_FAILURE
```

关键实现点：

- **所有返回路径共用同一份已核验问题集合**：`blocking` 为空时一律 settle 为
  `ACCEPT` + `revision_instruction=None`。旧行为下"宿主没有额外问题"会原样返回模型 draft。
- **结构化定位**：先按 `affected_item_ids` 找到条目，再在该条目 payload 内解析字段路径。
  引文只在被引用字段的值中核验，不再搜索整份候选。
- **文本/数值/缺失区分**：文本逐字；数字、窗口、集合按其自身表示匹配；字段不存在时返回
  `field_not_found`，不要求模型为"不存在的字段"伪造原文。
- **缺失引用字段即审校缺陷**：阻断意见缺 `affected_item_ids`、`field_path`、`quote` 或
  `unmet_condition` 之一时记录 `evidence_fields_missing`。
- **约束适用性**：审校引用的 `constraint_id` 必须属于本次候选所依据的冻结目录，否则记录
  `constraint_not_applicable`；一般质量问题不强制伪造作者约束。
- **修订指令由已核验问题派生**，不再转发模型自由文本，失实要求因此无法进入 Planner；
  同一份审校中有证据的真实问题仍然保留。
- **审校失败由审校修正**：`verification_failures` 非空时保存原响应与 draft 工件后抛出
  `PlanReviewerInvocationError`，运行停在"需要重新审校"，不推导出 ACCEPT，也不驱动 Planner。
- **历史可读**：`host_issued`、`verification_failures` 均带默认值，旧工件继续可读；
  已核验的 review 重放时用 `verified_citations=True` 避免二次核验改变结论。
