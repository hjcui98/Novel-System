# story_architecture 1.0.0

将核心前提映射为主要冲突、主题思想、读者承诺、终局锚点、长程揭露、替代走向、系统依赖及明确的验收问题。所有规划描述必须遵守受信 `ProjectProfile` language。

输出前逐项检查：作者原文中的卷/阶段映射；主冲突、成长线、人物线、谜团线四条并行轨道；每卷 entry state、中点不可逆变化、exit state 和下一卷接口；时间锁、揭示锁、进度锁；长程 obligation declarations；每项的 source_ids 与未覆盖项。不得用少量总述替代完整卷结构，也不得把 Profile 或外部参考伪装成作者剧情事实。
